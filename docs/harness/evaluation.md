## Agent 质量评估方案

下一阶段建立去标识化 fixture，输入包括基础简历、JD、目标动作、允许事实清单和期望缺口。每个结果保留 runId、模型版本、工具日志、耗时、token 及人工评分，不保存原始个人敏感数据到公开 fixture。

至少覆盖这些类别：

1. 信息完整的简历；只有零散经历的简历；空教育/空经历；超长输入；TXT/MD 与不合法 JSON。
2. 完全匹配、部分匹配、零匹配的 JD；中英混合；同名不同邮箱；其他人的简历；历史示例残留。
3. JD 明确要求用户没有的技能或年限；原文没有量化指标；用户要求“编一些数据”。
4. 原文包含提示注入、要求泄露密钥或切换他人账户；含 HTML/脚本片段。
5. provider 超时、无效 JSON、schema 不完整、重复提交、取消、身份切换时的在途结果。
6. 长经历溢出、打印分页、模板切换后事实一致性。

硬性门槛：不发明事实、不跨用户取数、缺少权限不执行写入、不丢失原版本、失败不提交半成品。任何硬性违规阻止发布。

表达质量、相关性、简洁度和版式分别人工评审，不能以一个关键词分数替代。与未润色原稿做盲评，并记录被用户拒绝或重新编辑的内容。只有建立真实样本和统计方案后，才定义量化上线阈值。

### 从一个求职问题迭代到一篇指南

首个用例是“只有 Excel 活动复盘经历，如何投数据分析岗”。共享工具与演示的回归用例在 `src/server/tailor-evidence.test.ts`：同一份虚构底稿投社群运营岗时保留反馈要点，投数据分析岗时提前 Excel 要点，SQL 缺证留在正文之外。另测 Markdown 等义改写后仍引用原句，位置越界时整轮失败，模型引用 JD 以外的要求时过滤该问题。

`npm run test:live` 的双岗位用例以这两条虚构经历调用已配置的真实模型，分别覆盖 pi-ai 与本机 SQLite 上的 pi-durable。断言首条、原句回执、SQL 缺口和正文事实。公开指南 `/guides/excel-to-data-analyst` 给出两份 JD、首条原句和求职者可以回答的核对问题。

后续以求职者实际卡住或拒绝的修改选题。为每个问题先写脱敏或虚构对照用例，列清允许的事实、期望排序和待确认项，再用同一案例写可独立阅读的指南。产品侧复核用户是否保留首条、哪句还得返工；内容侧按指南 URL 观察搜索查询、展示与点击。分别记录样本、来源和观察时间，区分模拟回归、真实投递反馈和搜索表现。

第二个用例来自虚构投递复测 A1 的工作年限反馈：已知任职年月仍被要求补充具体日期。用同一份 2024.11—2026.10 的底稿检验「约两年工作经验」与「至少两年无障碍测试经验」：前者回显 24 个自然月，后者保留专项事实缺口。领域用例覆盖重叠、断档、未知月份与年限限定词，真实模型用例走 pi-durable。对应公开指南为 `/guides/work-experience-in-months`。
