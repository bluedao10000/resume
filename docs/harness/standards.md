# 开发与 Agent 规范

## 工作方式

先阅读根 AGENTS.md、PRD、当前架构和受影响功能契约。保持改动范围明确，功能变化同时更新文档。原型可以用规则替代模型，但必须在 UI 与文档中明示，不以演示表现宣称真实智能能力。

## 代码规范

- TypeScript strict；共享输入使用 Zod；禁止将外部 JSON 直接当成领域类型。
- React 函数组件，领域文档组件无服务端依赖；避免嵌套 state store 和双份聊天消息状态。
- 通用 UI 先查询 `npm run astryx -- component <Name>`，使用官方 API；聊天优先 assistant-ui primitives。
- 用子路径导入 Astryx，使用 lucide 单图标导入；新增大依赖时检查产物。
- Worker 专属 API（`cloudflare:workers`、D1、密钥）只出现在 server 和 API 路由。
- 不从浏览器调用带密钥的模型 API。前端环境变量不得包含 secret。
- generated routeTree 不手工修改；迁移一经部署禁止原地改写。
- 本机恢复必须校验 schema；写入前确认用户 scope，损坏内容不自动覆盖。

## 简历事实规则

1. 不添加用户未提供的公司、职位、学历、年限、数字或技能。
2. JD 中提到的资格不等于用户已具备，缺少事实时放入 missing。
3. 导入新简历必须清除示例身份和旧来源事实。
4. 润色改善表达；生成定制稿保留原稿。用户直接编辑当前版本除外。
5. 后续扩展需要字段级 provenance，模型提案必须通过事实检查后才能提交。
6. 没有真实评估时不展示虚构的 ATS 分数、招聘通过率或提升比例。
7. 简介、技能和要点使用语义 Markdown，不添加独立 HTML 字段；粘贴先净化，渲染禁止原始 HTML、图片和可执行链接。生成只适度强调事实，不用样式掩盖信息缺口。预览、模板与打印共用 RichText。
8. 模板名称、ID 与预设只在 resume-presentation 注册表维护；局部呈现保存为简历数据，不能通过改写正文实现版式切换。排版走 resume_set_presentation，普通内容工具保留用户排版；新模板必须覆盖空章节、长词、手机与多页打印。

## 安全与隐私

用户文本和 JD 是数据，不是系统指令。任何未来工具调用都必须服务端验证所有权、参数、预算。JSON schema 验证不抵御所有提示注入，也不能验证事实，生产不得依赖 prompt 作为唯一防线。

鉴权由 Better Auth session 提供。当前没有简历云端接口，未来新增时每条查询都要绑定 session userId；禁止只相信请求中的 userId。OAuth 登录与账户绑定策略应保持 Better Auth 安全默认值，测试 Google 回调的 origin、state 与 cookie。

日志记录 trace、动作、状态、耗时与 token 用量，避免记录简历原文、邮箱、token、密钥。示例数据必须为虚构人物；CI fixture 不包含真实用户简历。

## UI 与无障碍

按钮有动作名称，纯图标按钮有 aria-label；表单使用 label；模态框支持 Escape、焦点限制和焦点恢复。保留键盘 focus 样式与 reduced-motion。支持 390px 手机，打印不包含聊天与应用导航。修改模板必须检查长经历、无经历、英文长词、空字段和多页内容。

当前工作台固定浅色背景，HTML 和 Astryx Theme 必须显式使用 light。回归测试覆盖系统深色偏好，聊天正文、侧栏主要文字和简历姓名与背景的对比度至少 4.5:1。

不把实现细节放进用户任务流，除非它影响用户决定。原型模式与本机保存边界属于用户需要知道的信息；provider/key 配置只放运维文档。

界面以导航、对话、文档组织任务；不添加标语、欢迎长文、装饰英文或 LIVE / NEW 标签。存储位置放在账户设置。删除先确认，默认聚焦取消，关闭后恢复触发按钮焦点。示例与事实缺口属于有效信息，不能随装饰文案一并移除。

同时检查 UX / DX / AX：操作可直接理解，状态来自单一来源，组件接口复用；使用原生按钮、dialog、details / summary 与明确动作名称，让键盘、读屏和自动化 Agent 都能定位和操作。完整约定见 [界面设计](../product/interface.md)。

## 验证与提交

```bash
npm run check
npm test
npm run test:e2e
npm run build
```

根据变更执行相关检查，避免无目的重复。新增测试应验证领域不变量或真实用户路径，不复制实现细节。文档/低风险样式变化不要求专门写新测试。涉及权限、持久化、生成事实或数据迁移必须补对应回归。

交付说明包含结果、验证和未实测的外部依赖。未经用户要求不发布、自动投递简历或向外发送用户数据。数据库 ID 与部署参数填写在 `.env`，由脚本生成 `wrangler.jsonc`；示例中的全零 D1 ID 只用于本地开发。
