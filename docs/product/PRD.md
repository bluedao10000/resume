# Folio 产品需求文档

版本：0.1 / 交互原型。负责人：待指定。更新：2026-11-14。

## 产品定位

Folio 是 chat-first 的简历管理 Agent。用户提供真实经历，Agent 通过整理、适度润色和岗位语境转换，将经历呈现为可核对、可编辑、可导出的简历。简历是有结构的数据资产；对话是表达目标和协作编辑的主要入口。

目标用户包括需要整理已有经历的求职者、面对多个 JD 需要维护不同投递版本的候选人，以及希望低成本迭代职业表达的在职人员。本阶段只提供个人工作空间。

## 核心原则

- 事实优先：不编造工作、教育、技能和量化结果。信息不足时要求补充。
- 聊天驱动：用户先表达意图，简历画布承接结果。也允许直接编辑，减少反复描述。
- 可追溯版本：定制生成新版本，基础简历保持可访问。当前原型以独立完整快照实现，后续增加 parentVersionId 与来源。
- 预览与导出同源：两种简历模板共享一个 schema，打印和 JSON 导出读取同一版本。
- 清晰说明能力：展示演示模式；不提供没有根据的 ATS 分数，不把关键词覆盖率称为求职成功概率。
- 界面克制：使用直接动作名称；不放营销标语、装饰标签或重复提示。每次界面调整同时考察 UX、DX 和 AX，见 [界面设计约定](interface.md)。

## 用户任务与验收

| 任务         | 用户路径                                 | 本阶段验收                                                                                           |
| ------------ | ---------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 整理一段简历 | 开始导入 → 粘贴或 PDF/DOCX/TXT/MD → 发送 | 新身份不继承示例公司的经历、教育、邮箱；原文保留；预览可编辑                                         |
| 润色已有经历 | 快捷操作或聊天 → Agent 返回              | 更新当前简历，保持 ID 与名称；展示修改说明；不添加未经证实的数字                                     |
| 针对 JD 定制 | 粘贴 JD → 检索已有简历 → 生成            | 从当前简历及最近 20 份同身份候选中按已知关键词选择来源；相关技能和经历靠前；缺口单列                 |
| 管理投递版本 | 简历库 → 搜索 → 选择 / 删除              | 选择只打开现有内容，不自动生成；支持逐份删除及当页撤销；删空后刷新不恢复示例；完全重复副本可手动清理 |
| 调整呈现     | 编辑或模板中心 → 预览                    | 姓名、职位、简介、联系、经历、技能、教育可修改；模板切换不修改事实                                   |
| 导出投递材料 | 导出 → PDF 或 JSON                       | 浏览器 A4 打印；JSON 保留全部结构，支持再次导入                                                      |
| 连接个人身份 | Google 登录                              | 配置后跳转 Better Auth OAuth；未配置时明确提示，仍可演示                                             |

## 对话与 Agent 行为

首次访问某个身份分区时，工作台展示虚构人物“林知夏”的示例草稿。列表、侧栏、画布和文档注明“示例简历”，打印保留虚构内容提示。示例与普通简历均可删除；删空后保存空库，刷新不重新预置。空库时可直接发送经历或导入文件创建简历；润色和 JD 定制须先有简历。用户可以直接发送带邮箱的多行简历、包含“岗位职责/任职要求/JD”的岗位描述；原型进行简单意图判断。其他输入按当前任务处理。历史对话按身份在本机保存，刷新恢复，侧栏可重开旧对话；后续消息携带有界历史上下文，新对话隔离上下文，新简历导入不继承旧人物事实。

简历库卡片和画布工具栏均提供删除入口。整份简历、编辑中的工作经历和重复副本清理均先确认，取消和 Escape 不改数据。删除当前项时切换到剩余第一份；删除非当前项保留选择。侧栏、简历库与预览立即同步，其他标签页的删除也同步。删除不触发 Agent。整份删除与清理支持最近一次操作的当页撤销；继续编辑、生成、导入、刷新或切换身份后失效。示例的润色或定制版本保留示例标识；新经历导入不继承标识，用户直接编辑内容后转为个人草稿。

未登录先展示独立落地页，生产 live 模式通过 Google 登录后进入工作台，退出后返回落地页。demo 模式提供显式试用入口。配置失败显示重试，不隐式切换模式。聊天字号统一，“本次草稿更新”默认折叠完整明细，事实缺口始终可见。

对话列独占视口高度：上方仅消息区，底部为输入框。导入、润色与岗位定制从输入框“＋”操作菜单进入，当前来源在输入框底部同行呈现。账户和手机预览切换放在侧栏，文档工具限制在右侧文档列。长消息只滚动消息区，不推动整页或遮住输入框。

演示路径：整理 → 规则润色或岗位检索/排序 → 更新当前稿或新增定制稿 → 人工核对。真实模型路径：校验 session → 检索事实来源 → pi-ai / pi-durable 调用模型 → 执行受控工具 → schema 校验、实际变更与身份归一化 → 更新预览。原型并非可自主规划多工具的完整 Agent harness。

输出必须说明做了什么、哪些信息缺乏依据。普通对话修改和润色直接更新当前简历，保持 ID、名称与列表位置，不因每轮对话新增一份。导入新简历和按 JD 定制才新增独立条目，定制不覆盖来源；后续继续修改定制稿也更新该稿。已有历史副本不自动删除，仍由用户确认清理。当前未实现聊天修改的完整历史与回滚。

## 本阶段范围

已实现：中文工作台、多对话本机存档与恢复、简历库本机持久化、访客/用户 ID 分区、结构化简历组件、PDF/DOCX 本地文字提取、语义富文本、两种模板、润色/导入/JD API、规则演示、pi-ai 模型访问和 pi-durable 原生持久化任务、Google OAuth 基础接入、D1 认证迁移、Workers 产物、交互与领域测试。

尚未实现：云端简历与聊天同步、扫描件 OCR、多模态附件、招聘平台抓取、多轮语义工具规划、流式 token、自动投递、协作、多语言模板、服务器端 PDF、完整事实溯源与回滚。简历库尚无独立重命名操作；可逐份删除，也可手动清理正文、名称和模板完全相同的重复副本，不合并有差异的投递版本。

## 隐私与权限

演示数据在浏览器本机保存；发送消息会经当前应用的 API 处理，演示 API 不持久化请求。live 模式将用户原文、必要的历史上下文及检索出的简历发送到配置的模型服务。pi-durable 额外在 Cloudflare DO SQLite 保存本轮输入、模型 transcript、任务和工具结果；删除本机简历不会清除该执行记录。Google 登录后使用不同的本机空间，访客草稿不会自动搬迁；可先导出 JSON，再登录后导入。退出账户不自动擦除本机历史数据，共享设备使用者应清理站点存储。

生产上必须按 session userId 在服务端实施访问控制。本机分区只是界面隔离，不代替服务端租户权限。

## 质量标准与衡量

原型门槛：主流程可用；输入错误清晰；取消不丢原稿；导入不串入示例事实；缺口不转成技能；刷新可恢复；390px 手机无横向溢出；A4 能打印；未配置 OAuth/模型不假装成功。

生产指标建议：首次可用草稿完成率、草稿到导出转化率、人工纠错率、每次生成新增事实的违规率、生成耗时 P50/P95、每份草稿成本。当前未采集行为分析，数值需真实试用后确定，不能以演示数据宣称提升效果。

## 迭代顺序

1. **M0 原型（本次）**：验证对话 + 文档双栏工作流、领域组件与部署技术栈。
2. **M1 个人可用**：D1 简历/版本/对话存储、所有权鉴权、结构化导入、流式状态、编辑撤销、文件提取。
3. **M2 Agent 核心**：工具注册、事实片段与来源、版本差异审批、问题澄清、JD 语义检索、回归评估与预算控制。
4. **M3 稳定交付**：服务端 PDF、质量检测、监控告警、配额限流、账户数据导出/删除、隐私策略和运行恢复。

章节移动是独立工具操作，`sectionOrder` 同时驱动预览、模板与打印。只读回答和无需修改的结果不写简历、不显示更新卡片。内容修改的确认文字由实际字段差异生成。durable 运行中刷新会恢复原请求；轻量模式中断后显示重新发送入口，不擅自重放。旧版本未曾存储的聊天无法补回。
